# Where the job search is kept

Apps differ in what they can save. Work out which case you are in before the first save. The user only needs to hear about it when they have to do something.

1. **You can already read and write files.** Use a `career/` folder where you are. Just say you will save their notes as you go, so they can stop and pick up any time. If the app makes the user choose a folder first, ask once in plain words and suggest one called Job Search. If the folder is inside a git repository, add `career/` to `.gitignore` first, since these files hold their resume and pay expectations.
2. **You can create and update documents in a project or workspace.** Keep each document there under the same name, and tell them to come back to this same project each time.
3. **You can only make files for download.** Keep everything in one file, `my-job-search.md`, each document under its own heading. At the end of every sitting, give them the updated file and ask them to save it and attach it next time. At the start of a sitting, if nothing is attached and you have nothing saved, ask for it first.

Only say something was saved when it was. If a save fails, say so and give them the content to keep.

Other skills add to the same place: `job-scout-ledger.md` (jobs seen, applications, feedback), `applications/<company>-<role>/` (the resume, note and interview brief for each job) and `linkedin-profile-log.md`.
