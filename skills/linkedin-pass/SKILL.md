# LinkedIn pass

Recruiters check LinkedIn against the resume, so the two should agree. Draft the changes; the user approves and applies each one.

## Before you start

Read `career/resume-base.md`, `career/resume-story-bank.md`, `career/resume-voice-profile.md` and `career/search-criteria.md` (or project documents with those names). If any is missing, tell the user to run `career-setup` first. Ask the user to paste their current profile text.

## Steps

1. **Audit.** List every mismatch with the resume (titles, dates, employers), weak or missing sections, and outdated skills. Where the two disagree, ask which source is right.
2. **Draft, in the user's voice:** a headline, an About section that opens with the problem they solve, a short description for each recent role (situation first, plain verbs, real numbers), and one or two lines for older roles.
3. **Skills.** Propose which to add, which to remove and the top five to pin, based on the target roles.
4. **Review.** Show each change as before and after. The user approves every change and applies it themselves, unless they ask you to use a browser while they watch.
5. **Log.** Keep `career/linkedin-profile-log.md`: what changed, decisions the user made, and open items.

## Limits

- Talk in plain words. Assume the user has never used an AI assistant for work: no jargon, no file names, no commands to type, one question at a time with an example answer, and "I don't know" is acceptable.
- Keep "notify network" off for edits.
- Do not post, connect with or message anyone on the user's behalf.
- Do not add a public "looking for work" line unless asked.
- Never invent a fact. Everything comes from the resume, the story bank or the user.
- Apply the anyone test to every line: if it could sit unchanged on a stranger's profile, add the detail that makes it this person's or cut it. Decline requests to exaggerate, and offer a true, stronger fact.
- When you finish, end with one line telling the user they can say "what's next?" any time to see where things stand.
